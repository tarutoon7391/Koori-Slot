`src/logic/` は v0.3 で本物の内部処理に差しかわりました（仕様書 `docs/spec.md`。変更点は `docs/CHANGELOG_logic.md`）。この約束がそろっていれば、演出側を直さずに動きます。

## 1. 台の窓口（`createMachine` が返すもの）

```js
import { createMachine, EVENTS, STRIPS, REEL_LENGTH, windowAt } from '../logic/index.js';

const machine = createMachine({ setting: 1 });   // setting: 設定 1〜6
machine.on(event => { /* event.type でイベントの種類を見る */ });
```

| 名前 | 中身 |
|---|---|
| `on(listener)` | イベントを受け取る。`listener({ type, ...データ })`。戻り値を呼ぶと受け取るのをやめる |
| `lever()` | レバー ON（ベットも自動）。回せないときは `false` |
| `stop(reel, press)` | 停止ボタン。`reel` は 0〜2（左・中・右）、`press` は押したときに上段にかかっていた図柄の番号。止まる位置（上段の番号）を返す |
| `snapshot()` | 表示用の状態：`{ credit, invested, paidOut, game, phase, normalGames, spinning, free, bonus, at }` |
| `debug` | 演出の確認用（3章） |

- 内部処理は、止まる位置（すべり）まで決めます。演出側は返ってきた位置までリールを回して止めるだけです。
- `STRIPS` はリール配列 v1.0（各 21コマ、上から順の番号）です。止まる位置 `top` の上段は `STRIPS[reel][top]`、中段は `top+1`、下段は `top+2` です。
- リールは下へ回るので、押してから k コマ滑ると上段は `top - k` になります。

## 2. イベント

1ゲームの順番は、次のとおりです。

1. `lever`
2. `notice`（レバーのとき）
3. `reel:stop` × 3
4. `game:end`
5. `notice`（止まったあと）
6. `stage` / `zencho:end` / `bonus:…` など

演出側は、第3停止のリールが止まりきるまで、`game:end` から後を見せません（進行役が待つ）。

### 1ゲーム

| type | データ | いつ |
|---|---|---|
| `lever` | `{ game, phase, free }` | レバー ON。`phase`: `'normal'` `'standby'`（ボーナス図柄をそろえるゲーム）`'bonus'` `'at'`（AT 中の前兆・特化ゾーンも `'at'`） |
| `notice` | `{ kind, timing, … }` | 演出の抽選結果（下の表） |
| `reel:stop` | `{ reel, top, slip, order }` | リールが止まる位置が決まった。`order` は何番目に止めたか |
| `game:end` | `{ cols, win, payout, credit }` | 3つ止まった。`cols[リール][段]` は出目。`win` は入賞した役（下の表）か `null`。**v0.3: 押し順ベルを間違えたときは `win: null`・`payout: 0`（取りこぼし。中段にベルが2つのこぼし目）** |

`game:end` の `win`（v0.2）：

| win | 中身 |
|---|---|
| `'bell'` `'replay'` | 揃った小役。`'replay'` は中段リプレイ揃い、`'bell'` は**右下がり**（左上段・中中段・右下段）のベル揃い（v0.3 で中段から右下がりに変更。中段のベル3つは作らない）。チャンス目は `'replay'`（再遊技）。押し順ベル（正解）と共通ベル（押し順不問。v0.3 で追加した役。見た目は同じ）はどちらも `'bell'` |
| `'cherry'` `'suika'` | チェリー・スイカ（ラインに関係なく役で払い出す）。払い出し枚数は `payout` |
| `'big'` `'reg'` | 中段に 7・7・7 / 7・7・BAR（入賞ラインは中段（リプレイ・ボーナス・こおりくん）と右下がり（ベル）の2本。v0.3） |
| `'koori'` | 中段にこおりくん・こおりくん・こおりくん。通常時の入賞（エピソードBIG）も、「こおりを狙え」の揃いも `'koori'`（v0.1 の `'epbig'` はやめて `'koori'` に統一） |

`notice` の種類（期待度に関わるので、内部処理が抽選します）：

| kind | データ | 見せ方（演出側） |
|---|---|---|
| `sakibare` | `{ timing: 'lever', pitch }` | 先バレ音。`pitch: 'high'` は AT 直撃（高くした音） |
| `flash` | `{ timing: 'afterStop', level }` | レア役のフラッシュ。`level`: `'small'` `'big'` `'rainbow'` |
| `cutin` | `{ timing: 'lever', color }` | 前兆中のカットイン。`color`: `'blue'` `'green'` `'red'` `'gold'` `'rainbow'` |
| `kakutei` | `{ timing: 'afterStop' }` | 確定音 |
| `iwakan` | `{ timing: 'lever', effect }` | （v0.4 新）違和感演出。AT 中（特化ゾーン中を除く）のレバーで出す。`effect` は下の表（イベントの種類の `type` と重ならないよう、名前は `effect`）。ボーナスか特化ゾーンに当たったゲームで出やすく、当たっていなくてもたまに出す（ガセ）。出す率は内部処理が決める |

|---|---|

| `'navQuestion'` | 押し順ナビが一瞬「？」になる（そのゲームに `nav` があるときだけ） |
| `'noise'` | 液晶にノイズが走る |
| `'mute'` | BGM が一瞬止まる |
| `'freeze'` | 液晶の絵が一瞬止まる |
| `'invert'` | 液晶の色が一瞬反転する |
| `'button'` | PUSH ボタンが勝手にチカチカ光る |
| `'lever'` | レバーの音が低く鈍い音になる |

|---|---|---|

| `zencho:battle` | `{ round, of, final, win, button }` | 前兆の最後の連続演出（1ゲームに1回）。`final` のときだけ `win`（倒せるか）と `button`（PUSH ボタンの色：`'white'` `'blue'` `'red'` `'gold'` `'rainbow'`）が入る |

- AT 中に規定ゲーム数（ゾーン・天井）に着いたときも、AT 中に前兆が始まってボーナスになります。

**AT 中のボーナスの流れ**（v0.2。内部処理の担当の変更希望を受けたもの）：

1. ボーナスの最初のゲームのレバーで `at:boss`（`final: false`）→ 相手の登場。
2. 特化ゾーンに当たった役を引いたゲームの次のゲームのレバーで `bonus:nerae`（`win: true`）→ こおりくんが揃う（`game:end` の `win: 'koori'`）→ そのゲームの終わりに `at:boss`（`final: true, win: true`）→ 演出側は「勝利 → 特化ゾーン確定」。勝ちを先に見せると、カットインの色の期待度が意味を持たなくなるため。
3. 当たらないままボーナスが終わるときは、最後のゲームのレバーで `at:boss`（`final: true, win: false`）→ 敗北。
4. AT 中のエピソードBIG は入賞した時点で特化ゾーン確定。**v0.3（演出側確認待ち）: 最初のゲームのレバーで `at:boss`（`final: true, win: true`）を出す**（相手の登場・勝利の見せ方は演出側の扱い。`bonus:nerae` は出さない）。v0.2 の「出さない」から変更。
5. ボーナスのあとは AT に戻ります。特化ゾーンに当たっていたら `tokka:start` から。

### 上乗せ特化ゾーン

1セット3G の自力継続型。演出は「魔王の褒美」「こおり大腸炎」の2パターンで、どちらにするかはプレイヤーが選びます（選ぶのは演出側。見せ方だけで、上乗せや継続の確率は同じ）。

| type | データ | いつ |
|---|---|---|
| `tokka:stock` | `{ stock }` | 特化ゾーンに当たった（AT 中のレア役・特化ゾーン中のレア役）。当たったゲームの終わり（`game:end` のあと）。AT 中のボーナスでの当選は、こおりくん揃いと `at:boss` で知らせるので出さない |
| `tokka:start` | `{ stock }` | 特化ゾーンが始まる。次のレバーから特化ゾーンのゲーム。`stock`: 始まったあとに残っているストックの数 |
| `tokka:game` | `{ set, game, add, guarantee, nav, hit }` | 特化ゾーンの1ゲーム（レバーのとき）。`add`: このゲームの上乗せ（5G 以上）、`guarantee`: このゲームのあとで継続が確定しているセットの数。**v0.3（演出側確認待ち）: `nav` を足した**（押し順ベルのゲームの押し順。特化ゾーン中も AT 中なのでナビあり。順押しナビは出ない）。`hit`: このゲームでリプレイ以上（リプレイかレア役）を引いた＝自力継続の条件を満たした（v0.5。おかランプのランプの点灯に使う） |
| `tokka:set` | `{ set, cont, revive }` | セットの3ゲーム目の終わり。`revive`: リプレイ以上を引けなかったが、継続率テーブルで続いた（「復活！」） |
| `tokka:end` | `{ total, sets, left }` | 特化ゾーンの終わり。`left`: AT の残りゲーム数（上乗せしたあと） |

- 特化ゾーンのあいだは `at:game` を出しません（AT のゲーム数は減らない）。上乗せは `tokka:game` の `add` で伝えます（`at:add` は出さない）。
- 特化ゾーンの途中で特化ゾーンをストックしたら、終わったときに続けて `tokka:start`。ボーナスをストックしたら、終わったときに前兆（`zencho:start` の `cause: 'stock'`）。
- AT のゲーム数が 0 になっても特化ゾーンのストックがあれば、`at:end` の代わりに `tokka:start`。

## 4. 内部処理（v0.3・本物）について

- 仕様書は `docs/spec.md`（Claude Docs「AT機（第3弾・仮称）仕様書 v0.1」の Markdown 書き出し）。仕様書の表（モード・ゾーン・ステート・レア役の当選率・ボーナスの振り分け・特化ゾーン・払い出しなど）はそのまま `src/logic/config.js` に写してある。
- 仕様書で未決の値（役の出現率・AT 中ベルの当選率・演出の振り分けなど）は `config.js` の【仮】（v1.0 たたき台）。変更点は `docs/CHANGELOG_logic.md`、シミュレーションの結果は `docs/sim_result.md`。
- 押し順ベルの取りこぼし：通常時はナビなし（内部で正解を決める。正解 1/4）、AT 中・ボーナス中・特化ゾーン中はナビあり。第1・第2停止までナビどおりなら 15枚、外れた時点で 0枚（中段にベルが2つのこぼし目）。順押しナビのゲームは押し順不問で 15枚。
- 共通ベル（押し順不問で 15枚。出目は押し順ベルと同じ）を新しく入れた（通常時のコイン持ちを 50枚で約 30G にするため。`config.js` の `commonBell` を 0 にすると無し。ユーザー確認待ち）。演出側には区別が要らない（`game:end` の `win` は `'bell'`）。
- イベントの順番・名前・データは v0.2 のまま。v0.3 で**足した**のは `bonus:game` の `nav`・`tokka:game` の `nav`・AT 中のエピソードBIG の `at:boss`（上の表の「演出側確認待ち」）。

### 2026-10-21 演出側からのお願い（違和感演出）

- **`notice` に `iwakan`（違和感演出）を足してください**（2章の表）。AT 中のレバーで、ボーナスか特化ゾーンに当たったゲームで出やすく、当たっていないゲームでもたまに出す（ガセ）。期待度に関わるので、出すかどうか・どの `effect` かは内部処理の抽選です。
