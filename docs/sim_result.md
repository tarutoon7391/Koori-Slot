# シミュレーション結果（内部処理 v1.0 たたき台）

`npm run sim`（`tools/simulate.js`）で、設定 1〜6 を各 300,000G 回した結果（seed 1、2026-10-21。ボーナス中の AT 当選率の弱チェリー・弱スイカを 9% に直したあとの値）。
数値は `src/logic/config.js` の v1.0 たたき台（仕様書で決定の表 + 【仮】の値）。
押す位置はでたらめ、押し順はナビがあればナビどおり、なければ中押し・右押しの4択からでたらめ（通常時の押し順ベルは 1/4 で正解）。

やり直すときは `npm run sim -- --games 300000 --seed 1`（`--setting 1` で設定1だけ）。

## 気になる点（数値は直していない。ユーザーの判断待ち）

仕様書では「機械割はプレイヤーが結構有利でよい」だが、たたき台のままだと有利すぎて台として成り立っていない。原因は仕様書で「決定」になっている表の組み合わせにあるので、どこを変えるかはユーザーに判断してほしい。

1. **機械割が設定1で 182%、設定6で 239%**（指示書の目安「設定1で 100% を大きく超える」に当たる）。AT 平均差枚も設定1で 1,500枚（目安の 1,000枚超え）。
2. **設定 3〜6 は AT がほとんど終わらない**。300,000G のうち通常時は設定5で 5,396G、設定6で 770G しかなく、最初の AT がそのまま続いている（設定5・6 の AT 平均・特化ゾーン突入率は AT が数回しか終わっていないので参考にならない。seed を変えると設定ごとの順番が入れかわるほど振れる）。設定差がレア役 +6%／段でも、AT が自力でループするので差が極端に出る。
3. **AT がループする仕組み**（仕様書どおりの動きで起きている）：
   - AT 中も規定ゲーム数（ゾーン・天井）が走り、ボーナス当選でゲーム数が 0 に戻って次のモードとゾーンを引き直す（0G ゾーン 10%、天国なら 100G 以内）。通常時のボーナス初当たり（約 1/100）がそのまま AT 中にも起きるので、AT 中のボーナスが 1 回の AT に平均 3〜4 回（設定1）入る。
   - AT 中のボーナスはそれ自体が純増（BIG 50G でベル 1/2.5 → 約 +150枚）で、BIG 41%・REG 19% で特化ゾーン（平均 +55G）。
   - AT 中のレア役はステート別の表で、超高確だと強レア役 100%・弱チェリー 40% がボーナスか特化ゾーン（1ゲームあたり約 1/50）。強レア役で低確 → 高確 100%、高確 → 超高確 50% なので、AT が長くなるほど超高確に居やすい。
   - 本前兆中の 1G連 ストックも AT 中に貯まる。
4. **通常時の初当たりが約 1/100 と早い**。通常時のレア役のボーナス当選率（低確で 1ゲームあたり約 1/190）と、0G ゾーン 10%・天国 50% の初期モードが効いている。ボーナス 1 回あたり AT は約 40〜50%（BIG 41%・REG 19%・エピソード 100%・1G連）。
5. **AT 直撃（リプレイの 1/400）はほとんど起きない**（設定1で 300,000G に 17 回）。通常時のゲーム数が少ない上に、前兆中は直撃しないため。

直すなら候補（決めるのはユーザー）：

- AT 中は規定ゲーム数を止める（AT 中のボーナスはレア役だけにする）か、AT 中のボーナス当選でゲーム数をリセットしない。
- AT 中のボーナス中の特化ゾーン当選率（`bonusAt` の表を AT 中は別に持つ）や、AT 中のレア役抽選の表を下げる。
- AT 中のボーナスの純増を下げる（`roles.bonus` のベルを AT 中だけ薄くする）。
- 通常時のレア役のボーナス当選率（仕様書「決定」）を下げる、または初期モード・0G ゾーンを見直す。
- 設定差をレア役 +6%／段より小さくする（AT のループに効きすぎる）。

上のどれかを決めてもらえれば、`config.js` を直して `npm run sim` をやり直す。
